# 基于真实图片的选图、图注与逐图核验

## 本次实际问题

用户截图显示 I5 为抽象图标，但稿件图注将其描述为小艺慧记操作界面；另外三张配图缺少逐图核验结果。旧代码在写作和重写时只发送图片名称等元数据，最后核验时才发送真实图片，容易产生基于名称猜测画面的图注。

## 修复

- 写作和重写均发送实际候选图片，并用 image_id 标签绑定。提示词要求基于画面选择图片、写客观图注，不能把图标称作操作界面或功能演示；不为凑更多图片使用不相关图。
- 写作输入只提供已提取事实、条件、对应引文和显式 allowed_product_fact_ids；全量产品原文保留在独立复核阶段，避免在注意事项里再次引入尚未绑定事实 ID 的功能或条件。
- 逐图核验明确列出所需图片编号和每张图注，接收独立 image_checks 数组；旧版 image 检查仍兼容。每张选用图片都须有有效检查，缺失时显示具体 I 编号并保持待复核，图文错配仍阻止最终交付。
- 修稿输入包含服务器保留的上次问题和真实候选图。「按问题修稿并核验」执行一次修稿再核验；「只重新核验」保留原稿执行核验。两者均由用户点击触发，不自动重试。
- 核验页将需处理项、待复核项置顶，通过项折叠，显示数量，避免问题埋在大量通过项之后。
- 不新增依赖、不更改原有产品事实来源和最终交付门槛。候选图片总量上限 10MB；超出时明确要求减少选图，不静默丢图。

## 验证边界

150 项隔离回归通过，包含写作接收真实图像输入、写作事实范围、重写接收图片及原问题、逐图返回覆盖、无效或缺失图片编号阻止通过、真实图文错配保持 blocked。

真实浏览器在 1440×1000 和 390×844 使用模拟资料复现 I5 错配及 I1/I2/I3 漏检：四项问题置顶，通过项折叠，最终导出保持禁用；点击修稿后模拟正确选用 I1/I2/I3，逐图检查通过才恢复导出。无横向溢出或脚本异常。虚构测试图不作为真实产品素材或真实营销结果。

真实官网任务的首轮验收已实际让写作模型看到 6 张图，最终选择 I1/I3/I6 三张；三张图均获得有效画面检查，未再漏图或把 I5 当作界面。该轮仍有两项事实/合规问题，因此整体标记 blocked，没有记为完整通过。后续写作事实范围收紧后的真实运行结果另行记录。

收紧写作事实输入后，再次按大学新生开学、小红书、HUAWEI MateBook 14（鸿蒙版）执行真实官网任务。初稿仍为 blocked；在本次验收中模拟一次显式的按问题修稿操作后，最终状态 ready，待处理项为空，选用 I1/I3/I2/I4 四张图，每张均返回有效画面核验结果。共调用 1 次事实提取、2 次带图写作/修稿、2 次带图核验；没有自动循环重试，没有调用 ima 或 QwenImage。

这是单个官网场景的自动核验通过记录，不替代人工复核，也不代表 ima 流程或其他型号、平台均已验收。安全摘要记录于本地 artifacts/image-grounding/live-ad-check-final.json，不含凭证或知识库原文。
