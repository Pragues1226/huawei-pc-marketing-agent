# 复赛创新方向

这份清单把赛题评分、当前工作台能力和 GameForge OS 的创意流程经验放在一起梳理。目标是让评委能看见 Agent 怎样理解任务、怎样使用证据、怎样检查输出，而不是只看到一篇生成的软文。

## 先做这五项

| 优先级 | 创新点 | 怎么做 | 对应评分关注点 | 当前状态 |
|---|---|---|---|---|
| P0 | 需求契约 | 把用户原话整理成目标人群、使用情境、购买阶段、内容目标和平台；每项标出原始输入或“待补充”。生成前只追问会改变策略的缺项。 | 业务场景理解 20、自研 Agent 15 | 策略页已展示当前表单的六项需求字段、来源、必填完整度与缺项入口；不宣称抽取或保存自然语言原话。购买阶段按选填处理。 |
| P0 | 场景切换对照 | 固定型号，分别运行开学、差旅、创作等任务，并排展示切入点、事实优先级、配图用途和行动引导的变化。 | 业务场景理解 20、图文质量 15 | 规则演示可对照当前任务与替代场景，并一键带回表单重跑；真实资料任务仍需重新检索与核验。 |
| P0 | 平台转译对照 | 固定产品与目标人群，一键对照公众号、小红书、朋友圈；检查结构、语气、配图数量和 CTA 是否真的变化。 | 平台适配 15、功能体验 10 | 规则演示可生成三平台草稿，自动归纳发生变化的结构/标题与正文/语气/图数/标签/行动引导，并复制摘要或导出 Markdown；单个平台失败不会丢掉另外两版；真实资料核验仍需按目标平台重跑。 |
| P0 | 逐条事实链 | 每个产品声明绑定 ima 原文摘录、来源标题、适用条件；从预览段落或核验卡跳转到关联事实依据。无来源或条件冲突时不进入可交付稿。 | 产品事实 20、图文引用 15 | 生成链路提取原文引文并把声明核验映射到事实 ID；预览及核验卡支持跳转到对应事实卡，无事实 ID 的声明显示未关联提示。当前机器未配置 ima/模型凭证，真实端到端结果仍待复核；模型结论仍需人工检查。 |
| P0 | 图片同型号校验 | 图片候选与型号、图片来源、说明文字、建议插入段落一起显示；型号不一致或来源缺失时阻止选用。 | 产品事实 20、图文引用 15、合规安全 5 | 真实生成链路会把实际图片交给独立模型核验；图片核验项可跳到对应图、图注与来源。当前本机缺少 ima/模型配置，端到端效果仍待实跑；模型结论不能替代人工确认。 |

## 有辨识度的增强项

1. **三种不同的表达方向。** 规则演示现可在固定任务和平台下，选择需求清单、一日流程、真实任务体验三种不同内容顺序并重跑整篇示例。它们只使用任务信息，不冒充真实产品事实；真实资料方向仍需结合已核验的产品事实进一步实现。
2. **独立需求审阅。** 生成后由单独的审阅上下文核对用户原话、目标与平台要求，检查偏题、重复和“看起来不同但策略没变”。生成者不自评通过。
3. **反例压力测试。** 当前四个本地规则用例支持依次运行、逐项查看与导出演练报告；报告只记录已运行的实际返回，明确不代表模型语义或法律核验。易混型号和竞品对比等完整模型边界仍待真实任务验证。
4. **按证据改写。** 用户指出某条事实或角度有问题时，只重写相关段落，并重新检查受影响的图片和声明；保留未受影响部分及其核验记录。
5. **事实冲突卡。** 当不同资料的型号、版本或条件不一致时，并列展示原文与差异，要求人工选择依据，不用模型自行猜测。
6. **图文叙事板。** 每张 ima 图片对应一个段落、一个读者问题和一个解释用途，让图片承担信息，不作为装饰素材。
7. **需求变化回放。** 当前可选择最近的开发演示，比较实际保存的任务字段、切入方向、切入点、内容优先级、开场、正文结构、标题、CTA 和配图数量；手工修改前后的标题、正文与行动引导差异可逐次回看，最多保留最近五版。
8. **发布前风险闸门。** 明确分开事实无依据、图片待确认、合规风险和平台格式问题；阻断理由可查看、可修正，不用单一“通过率”掩盖问题。
9. **三层质量记录。** 确定性规则检查、独立模型审阅、人工结论与备注目前分开显示并随真实结果导出；人工记录只保存在当前运行内存。真人试用采用情况和真实发布效果仍需另行取证，不把模型结果当成用户反馈。
10. **可复现的提示词版本。** 把场景分析、平台结构、知识库边界、图文规则和核验要求拆成可维护模块；每次输出记录用到的规则版本。
11. **证据覆盖图。** 来源页已有声明—事实关联总览，标记未关联声明，并可跳转到 ima 原文事实卡；模型状态和人工确认分开显示。任务、配图和检查结果的完整连接图仍可继续增强。
12. **导购现场口袋卡。** 将已核验的图文策略压缩成“先问什么、可说明什么、哪些要确认”的导购提示，适合门店现场沟通；仍需使用真实来源。
13. **活动版本锁定。** 活动日期、价格和权益默认标记为易过期信息；没有当期来源就要求补充，不把旧活动内容带入新任务。
14. **人工反馈回流。** 记录用户实际选择了哪个方向、改了哪里、为什么改；若团队取得真实发布反馈，再关联真实数据。没有数据时只保存观察，不虚构转化结论。
15. **一键复赛任务集。** 固定三组基础用例，再加换场景、换平台、易混型号和缺失价格的干扰用例；导出每次运行的真实输入、来源与检查结果，方便录屏和复核。
16. **任务变更失效保护。** 输入条件改变后标记旧稿并暂停复制、导出和编辑；真实模式更换产品型号时清空旧检索结果、已选原文与图片，避免把不同任务或型号的结果混用。

## GameForge OS 方法如何迁移

GameForge OS 的可借鉴之处是把原始需求连到候选方案、验收条件和质量证据，并让独立审阅、自动 QA 与真人观察各自保留来源。放到营销 Agent 中，对应为：用户需求原话 → 内容策略与事实依据 → 平台化稿件 → 逐项核验 → 人工确认。IP 适配检查改成场景和平台差异检查；玩法 QA 改成事实、图片、合规和格式核验；试玩记录改成真实运营人员的修改与采用观察。

这些方法是产品路线建议，不表示当前版本已经实现三方向生成、自动图片型号识别或真实发布效果分析。独立模型复核已有单独核验步骤，但仍需人工检查，也不代表评审结果已被实跑验证。当前已实现能力与待完成边界以 README 和工作台说明为准。

## 复赛演示顺序

1. 输入一项完整任务，展示场景判断与真实 ima 检索。
2. 打开来源，回到原文和图片；说明型号与适用条件。
3. 固定产品更换场景，指出策略变化；再固定任务更换平台，指出结构、语气、图数和 CTA 变化。
4. 输入缺失价格或相近型号，展示追问或拦截；不补造结果。
5. 修改一项意见，重新检查，再导出带来源的结果。

赛题要求复赛视频展示真实运行过程，至少三组优秀运行结果、至少两类场景和两个平台；演示中应清楚区分开发演示、真实 ima 资料与已完成的核验。
