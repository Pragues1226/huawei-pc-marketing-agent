# 首版开发与后续迭代

从当前进度继续：由仓库拥有者集中完成第一个真实可运行的完整版本，再让协作者基于同一基线迭代。当前不按人分配模块，也不重新计算比赛起始时间。

## 已有基础

- [x] 本地浏览器工作台及任务输入。
- [x] 指定 ima 共享库连接、目录浏览与资料检索。
- [x] 产品原文、真实图片和带来源的资料调用包。
- [x] 三平台规则演示、结构检查、编辑与导出。
- [x] 模型生成、逐字引句事实提取和独立核验管线。

## 首版集中推进顺序

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| 1 | 模型调用与提示词接入 | 已实现；待用正式模型配置做真实验收 |
| 2 | 资料转为事实依据 | 已实现逐字引句、型号、适用条件和来源关系 |
| 3 | 真实图文生成 | 已实现三平台文案与实际图片引用 |
| 4 | 事实、图片与表达核验 | 已实现自动核验与阻断；仍需发布前人工终审 |
| 5 | 修改与最终导出 | 已实现修改后重新核验，未通过时停用复制与导出 |
| 6 | 固定完整基线 | 待保留一组真实运行结果并从干净环境复现 |

首版先用一个明确型号、一个场景和一个平台跑通全流程。这是后续迭代基线；其他平台、场景与提交材料仍需按赛题要求补齐。

## 首版验收

- [ ] 真实任务能从输入走到图文结果，不依赖开发演示内容。
- [ ] 声明可回溯 ima 原文，图片来源和适用型号一致。
- [ ] 无依据的信息不进入最终稿，冲突和未确认项有明确提示。
- [ ] 支持一次真实修改、重新核验与导出。
- [ ] 从最新 main 按 README 可复现，运行结果与文档一致。

首版通过验收后，协作者再从最新 main 建立按改进目标命名的分支，提交小范围 PR，由仓库拥有者统一集成。

## 后续候选改进

- 场景与平台质量：补足受众、购买阶段和三平台的真实差异。
- 准确性：易混型号、版本条件、价格时效与图片适用性。
- 体验：异常提示、生成耗时、修改及导出。
- 参赛交付：魔搭、说明书、真实结果、复赛录屏及评审访问。

这些是改进方向，不预先绑定人员。见 [验收任务](acceptance.md) 与 [提交清单](submission.md)。
